# Spec: Fix the six HIGH-severity audit findings (H1–H6)
Version: 2

## Goal
Make catalog approval and inventory stock authoritative on the write side and replayable, make TND one millime convention end to end so operators can enter 15.3 DT or 153894.32 DT exactly, make checkout stop and reconfirm a changed quote, and make `projection:replay` real and enforceable — without regressing the current guards, atomic stock behaviour and order snapshots.

## Corrected prompt
Use the same `/spec` command defined under `.agent` in Qoder, then fix the HIGH-severity problems found in the preceding audit.

## Open questions
- [resolved 2026-10-29] The user requires decimal DT entry (`15.3 DT`, `153894.32 DT`), so TND is configured with three decimals (millimes) and existing whole-dinar rows are migrated ×1000 once. No blocking question remains.
- [minor] What should happen to shipping values already saved through the old millime UI, for example 15000 before this migration? Default if unanswered: the ×1000 migration treats every stored shipping value as whole dinars, so 15000 becomes 15 000 000 (15 000 DT); if an operator had already entered millimes, they re-enter the fee after deployment and the runbook says so.
- [minor] Should the cart page also show a price-change banner, or only checkout? Default if unanswered: the cart exposes `priceChanged` and the checkout blocks with the warning; no separate cart-page banner.
- [minor] Should the reviewer-save approval reuse `CATALOG_SUBMISSION_APPROVED` or add a distinct `CATALOG_PRODUCT_APPROVED_BY_EDIT` action? Default if unanswered: reuse `CATALOG_SUBMISSION_APPROVED`.
- [minor] Should `published` move into `catalog_submission`? Default if unanswered: no, it stays in `storefront_product_view` and remains a separate command.
- [minor] Should `projection:replay` also reindex Meilisearch? Default if unanswered: no; `app:storefront:index-search` remains the separate documented step.
- [minor] Should a missing `confirmedQuote` return 409 or 422? Default if unanswered: 409 with `reason: "confirmation-required"`, so the client can recover by resubmitting the current quote from the response.

## Out of scope
- Medium and low audit findings, including payment-failure compensation, delete-user PII and orphan cleanup, review verification policy, `parent_slug` legacy cleanup, slug immutability, and BRS race conditions RC4–RC11.
- A full catalog content write model for products and categories, event sourcing, an event store, or aggregate rehydration from events.
- Migrating product, cart, order, payment or shipping amounts to millimes, and sub-dinar price support.
- An append-only inventory movement ledger; `inventory_stock` plus `inventory_reservation` is the stock record for this scope.
- Renaming `_minor` columns or `price_minor` API fields.
- Replaying or reindexing Meilisearch as part of `projection:replay`.
- Multi-currency support, FX, tax, invoicing, promo redesign and rounding policy beyond the declared TND scale.
- A maintenance window, dual write, feature flag or zero-downtime cutover plan.
- Admin proxy order changes, admin UI redesign beyond the shipping fields, and a cart-page redesign.
- Any change that exposes approval metadata in public storefront payloads.
