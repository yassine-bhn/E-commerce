# Spec: Close the six remaining limitations of the Super Admin approval workflow
Version: 1

## Goal
Each of the six limitations the approval-workflow report still carries ends this run with executed evidence — a test, a migration or a production change — or, where the limitation is a judgement no test can make or a loss no migration can undo, with an explicit statement saying so in place of "INSPECTED".

## Corrected prompt
The Super Admin approval workflow still has six documented, unfixed limitations: R39/R40/R58 were only verified by inspection; moving a product to another category is only covered through the generic update path (R42); the transactional proofs stop at statement level (R38); `customer_profile.email` has no unique index; the approval migration is reversible in schema but not in state — its `up()` re-approves and re-publishes every row after a `down()` — and its backfill violates MIG-002 because a migration writes the read model, which is said to need a new migration; and the reviews guard lives at the HTTP edge in breach of QRY-004 while raising the endpoint from 2 to 3 statements, which no test pins. Fix them.

## Assumptions

## Open questions
- [minor] Rewrite the approval migration in place, or add a migration that supersedes it? Default if unanswered: rewrite in place, because a later migration runs *after* the re-executed `up()` and therefore cannot stop the blanket `UPDATE` the prompt complains about. See Decisions D1.
- [minor] Should `POST …/reviews` to a hidden product stay 404 rather than become 409? Default if unanswered: 404, unchanged (R20).
- [minor] Should the backfill command default to dry-run? Default if unanswered: yes, `--apply` is required to write.
- [minor] Should the crash proof use a child PHP process or only a second connection? Default if unanswered: both, the connection proof being the deterministic one.

## Out of scope
- Changing the approval state machine, the three statuses, the decision matrix or the public payloads.
- Adding a `projection:replay` command (it does not exist in this tree); the legacy backfill is a one-off operator command instead.
- Unique constraints on any column other than `customer_profile.email`.
- Redesigning `catalog_audit_log` or `identity_audit_log`; the existing shape is asserted, not changed.
- Frontend work, new dependencies, unrelated refactoring.
- Backfilling approval metadata into public responses.
